## Picker/UI Comparison Notes — mini.nvim upstream vs local snacks extra

### Scope observed in this worktree

- Upstream `ui.lua` now uses `mini.files`, `mini.tabline`, `mini.bufremove`, `mini.diff`, `mini.statusline`, and `mini.icons` directly ([lua/plugins/ui.lua](lua/plugins/ui.lua)).
- Local snacks picker stack still exists in `extra/` and remains heavily customized via [lua/plugins/extra/snacks.lua](lua/plugins/extra/snacks.lua), [lua/utils/snacks_pickers.lua](lua/utils/snacks_pickers.lua), and [lua/utils/editor_keymaps.lua](lua/utils/editor_keymaps.lua).
- Result: the rebase did not fully replace snacks-based workflows; upstream changed the default UI baseline, but local custom picker workflows still depend on `Snacks.picker.*`.

### High-level architectural difference

- **mini.nvim approach**: small focused UI modules with limited built-in workflow surface. Examples in upstream:
  - `mini.files` for filesystem browsing with lightweight mappings and manual refresh/filter hooks ([lua/plugins/ui.lua](lua/plugins/ui.lua))
  - `mini.tabline` for listed buffer navigation only ([lua/plugins/ui.lua](lua/plugins/ui.lua))
  - `mini.diff` for hunk navigation/apply/reset only ([lua/plugins/ui.lua](lua/plugins/ui.lua))
- **snacks approach**: one broader interaction layer with integrated picker, explorer, dashboard, terminal, notifier, image, quickfile, and extra picker actions/layout controls ([lua/plugins/extra/snacks.lua](lua/plugins/extra/snacks.lua)).
- Practical impact: mini gives a lean default UI; snacks remains the richer workflow engine.

### Picker UI differences

#### mini.pick / mini-style stack

- Upstream migration notes mention `mini.pick`, but the current `ui.lua` in this worktree does not define a full `mini.pick` customization layer yet; the visible upstream UI emphasis is more on `mini.files` and other mini modules than on custom picker workflows.
- Mini modules shown here expose relatively small config surfaces:
  - `mini.files.mappings` remaps navigation keys, help, sync, and trim behavior ([lua/plugins/ui.lua](lua/plugins/ui.lua))
  - custom hidden-file toggle and copy-path behavior are added manually with autocmds and buffer-local mappings ([lua/plugins/ui.lua](lua/plugins/ui.lua))
  - floating placement is manually adjusted by calling `nvim_win_get_config()` / `nvim_win_set_config()` on `MiniFilesWindowOpen` and `MiniFilesWindowUpdate` ([lua/plugins/ui.lua](lua/plugins/ui.lua))
- This indicates a more manual composition model: basic primitives are available, but extra UX polish is implemented ad hoc in Lua.

#### snacks.picker stack

- Snacks exposes a much larger picker UI surface directly in plugin opts:
  - source defaults (`picker.sources.files.hidden`, `follow`) ([lua/plugins/extra/snacks.lua](lua/plugins/extra/snacks.lua))
  - layout defaults (`picker.layout.layout.backdrop`) ([lua/plugins/extra/snacks.lua](lua/plugins/extra/snacks.lua))
  - formatter tweaks (`picker.formatters.file.filename_first`) ([lua/plugins/extra/snacks.lua](lua/plugins/extra/snacks.lua))
  - previewer settings (`picker.previewers.git.native`, `cmd`) ([lua/plugins/extra/snacks.lua](lua/plugins/extra/snacks.lua))
  - icon toggles (`picker.icons.files.enabled`) ([lua/plugins/extra/snacks.lua](lua/plugins/extra/snacks.lua))
  - per-window keymaps including picker input mappings (`picker.win.input.keys`) ([lua/plugins/extra/snacks.lua](lua/plugins/extra/snacks.lua))
- Snacks also supports picker-specific footer text, separate input/list keymaps, toggles, and action injection in custom pickers ([lua/utils/snacks_pickers.lua](lua/utils/snacks_pickers.lua)).
- UI-wise, snacks is materially more configurable out of the box than the mini setup currently present in this branch.

### Feature parity findings

#### File explorer / file browser

- **mini.files provides**:
  - directory navigation
  - hidden-file filter toggle via custom `refresh()` wrapper
  - copy-path custom action
  - floating window position override
- **snacks explorer/picker provides**:
  - explorer entrypoint plus picker-based file browsing with layout presets such as `vertical` and picker-specific key overrides ([lua/plugins/extra/snacks.lua](lua/plugins/extra/snacks.lua), [lua/utils/editor_keymaps.lua](lua/utils/editor_keymaps.lua))
  - broader reuse of picker state helpers from local utilities for cwd, search, live mode, and toggles ([lua/utils/editor_keymaps.lua](lua/utils/editor_keymaps.lua))
- Conclusion: mini.files covers basic browsing, but snacks covers more search-oriented and stateful file navigation workflows.

#### Buffers

- **mini.tabline + mini.bufremove** cover:
  - previous/next buffer navigation
  - close left/right/others via small helper functions ([lua/plugins/ui.lua](lua/plugins/ui.lua))
- **snacks.picker.buffers** additionally supports:
  - buffer list as a searchable picker
  - hidden/nofile buffers (`buffers { hidden = true, nofile = true }`) ([lua/plugins/extra/snacks.lua](lua/plugins/extra/snacks.lua))
  - room for custom buffer filtering actions in picker mappings ([lua/utils/editor_keymaps.lua](lua/utils/editor_keymaps.lua))
- Conclusion: mini buffer UI is lighter and static; snacks buffer UX is richer and more interactive.

#### Git / diff workflows

- **mini.diff** in upstream currently provides:
  - hunk navigation (`first`, `prev`, `next`, `last`)
  - apply current hunk
  - reset current hunk ([lua/plugins/ui.lua](lua/plugins/ui.lua))
- Missing compared with earlier local git workflows:
  - no direct replacement for gitsigns buffer unstage (`<leader>ghU`) noted in this rebase log
  - no evidence here of commit-range file pickers, upstream diff file selection, or remote-open actions in mini
- **snacks custom git pickers** provide significantly more workflow depth:
  - custom command-backed pickers using `snacks.picker.source.proc` ([lua/utils/snacks_pickers.lua](lua/utils/snacks_pickers.lua))
  - dynamic commit range stepping for `HEAD~N..HEAD` with live title updates and picker refresh ([lua/utils/snacks_pickers.lua](lua/utils/snacks_pickers.lua))
  - custom preview functions for git diff against arbitrary base refs ([lua/utils/snacks_pickers.lua](lua/utils/snacks_pickers.lua))
  - custom actions such as remote-open and file diff handlers ([lua/utils/snacks_pickers.lua](lua/utils/snacks_pickers.lua))
- Conclusion: mini.diff is only partial parity for signs/hunks, not for the custom git picker workflows built around snacks.

#### Search / grep / navigation

- Upstream mini-side shown in `ui.lua` does not currently expose an equivalent custom search picker layer.
- Local snacks mappings cover:
  - standard grep/files/recent/help/lines/qflist/registers/projects/grep_buffers/snippets/zoxide/smart pickers ([lua/plugins/extra/snacks.lua](lua/plugins/extra/snacks.lua), [lua/utils/editor_keymaps.lua](lua/utils/editor_keymaps.lua))
  - stateful picker initialization via helper utilities for visual selection, smartcase/ignorecase, cwd targeting, and monorepo/subproject modes ([lua/utils/editor_keymaps.lua](lua/utils/editor_keymaps.lua))
- Conclusion: current snacks config remains much broader than the visible upstream mini configuration for interactive search workflows.

### Custom picker support

#### snacks custom picker support is confirmed and already in heavy use

- Local code defines many custom pickers in [lua/utils/snacks_pickers.lua](lua/utils/snacks_pickers.lua), including:
  - session picker with custom save/delete actions and refresh semantics
  - tmux window picker
  - git range / upstream diff / command-result pickers
- Existing patterns show snacks supports:
  - static item lists via `items`
  - dynamic sources via `finder`
  - custom item formatting
  - custom preview callbacks
  - custom actions
  - custom input/list keymaps
  - live refresh without closing picker
- The memory note in [docs/memory/snacks_picker.md](docs/memory/snacks_picker.md) also documents non-trivial picker constraints such as mandatory `text` fields, dynamic finder refresh behavior, and source-buffer caveats.

#### mini custom picker support

- It likely supports custom sources conceptually, but based on the files inspected here there is no equivalent local mini custom picker library yet.
- No evidence in current worktree of mini-based custom pickers matching the snacks utility layer for sessions, tmux, custom git refs, monorepo-aware grep, or dynamic explorer-like state transitions.
- So for this repository specifically, snacks is the proven custom picker platform today.

### UI/UX tradeoff summary

- **mini upstream baseline advantages**:
  - simpler defaults
  - fewer moving parts
  - lighter plugin surface
  - good enough for tabline, file browser, statusline, icons, and basic diff navigation
- **snacks local stack advantages**:
  - richer picker UI knobs
  - better preview pipeline
  - built-in dashboard/explorer/terminal integration
  - first-class custom picker implementation path already used throughout local utilities
  - more suitable for power workflows and repository-specific commands

### Rebase implication

- The upstream migration to mini should be read as a baseline simplification, not as a full replacement for the local snacks workflow layer.
- Keeping `lua/plugins/extra/snacks.lua` was necessary because local code still depends on advanced snacks picker behavior and custom picker infrastructure.
- If future cleanup is desired, the realistic split is:
  - keep mini for baseline UI modules (`files`, `tabline`, `statusline`, `icons`, `diff`)
  - keep snacks for advanced pickers, explorer workflows, and custom interactive tooling
  - only migrate away from snacks after replacing the utilities in [lua/utils/snacks_pickers.lua](lua/utils/snacks_pickers.lua) and related actions/keymaps

### Short answer to parity question

- **Does mini provide similar config settings?** Partially. It covers some of the same UI areas, but with a much smaller and more manual configuration model in the current upstream setup.
- **Does mini provide custom picker capability comparable to current snacks usage?** Not in this repository today. Snacks already has a mature custom picker layer here; mini would require new implementation work to reach similar workflow coverage.
