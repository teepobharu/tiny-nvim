GPT-5.2 CodeCompanion Adapter Fix - Pre-Implementation Checklist
================================================================================

ISSUE:
- CodeCompanion sends "max_tokens" parameter
- GPT-5.2 rejects it, requires "max_completion_tokens" instead
- Error: 400 invalid_request_error on max_tokens parameter

ROOT CAUSE:
- CodeCompanion schema-to-parameters mapping is 1:1 pass-through (no renaming)
- Agoda OpenAI Proxy is pass-through (no parameter translation)
- Parameter names must match API expectations exactly

================================================================================
INFORMATION GATHERED:
================================================================================

✅ CodeCompanion Architecture
   - Schema key names map directly to request parameters
   - No built-in parameter renaming or translation
   - Mapping path controls nesting (e.g., "parameters" → adapter.parameters.*)
   - Default values applied via make_from_schema() → map_schema_to_params()

✅ OpenAI Endpoint Requirements
   - Chat Completions (/v1/chat/completions):
     * Uses: max_completion_tokens (not max_tokens)
     * Uses: temperature, top_p (only when reasoning_effort = "none")
     * Uses: reasoning_effort (optional, default = "none")
   
   - Responses API (/v1/responses) [not in use]:
     * Uses: max_output_tokens (not max_tokens)
     * Uses: verbosity (low/medium/high)
     * Better for reasoning models

✅ GPT-5.2 Constraints (per OpenAI docs)
   - ❌ Does NOT accept: max_tokens
   - ✅ DOES accept: max_completion_tokens
   - temperature/top_p only allowed when reasoning_effort = "none"
   - Default reasoning_effort = "none" (so temperature OK by default)

✅ Current Setup Issues
   - File: lua/utils/my_codecompanion_utils.lua
   - Problem: Uses "max_tokens" in schema (inherited from openai.lua)
   - Result: GPT-5.2 rejects requests with 400 error

✅ Adapter Schema Examples
   - max_tokens:
     mapping = "parameters"
     default = 4096
     → Emits to adapter.parameters.max_tokens
     → Sent in request as "max_tokens": 4096
   
   - ["reasoning.effort"]:
     mapping = "parameters"
     → Emits to adapter.parameters.reasoning.effort
     → Sent in request as "reasoning": {"effort": "medium"}
